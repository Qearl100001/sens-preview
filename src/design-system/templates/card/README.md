# 卡片样板间

> 卡片在真实业务页面中的组合与验收规则。
> 成熟度：Pilot
> 实现：Implemented
> 验证：Pending
> 来源：Figma 页面、业务页面结构与 `SensCard` / `SensEntryCard` 组件规则
> 预览：`/templates/card/*`

## 样板间定位

卡片样板间用于还原卡片在真实业务页面中的使用方式。用户提供的是页面时，样板间应还原页面，而不是把卡片拆成脱离上下文的静态样张。

样板间负责承接：

- 页面标题、说明、导航、内容区和页面层级；
- 卡片分组、排序、栅格和页面容器关系；
- 页面中的真实入口、操作和状态反馈；
- 卡片与页面其他组件之间的组合关系；
- 页面在规定验收宽度下的布局表现。

基础组件页负责验证 `SensCard` / `SensEntryCard` 的结构、token 和状态矩阵；卡片样板间负责验证这些组件在真实页面中的组合，不把业务页面规则反向写入卡片 API。

## 页面还原规则

### 1. 以页面为还原单位

- Figma 或业务资料给出完整页面时，按完整页面结构实现。
- 页面壳、标题栏、导航、内容分组、操作区和浮层关系应保留；不得只截取卡片区域作为最终样板间。
- 页面中的留白必须能解释为页面层级、布局间距、内容承载或响应式约束；不能为了填满演示区域制造无语义空白。
- Figma 固定宽度只用于对照；实现应由页面容器、栅格和组件规则共同决定，不复制不必要的固定宽度。

### 2. 以真实组件为承载

- 卡片必须使用已录入的 `SensCard`、`SensEntryCard` 或其他 Sens 组件。
- 页面中的按钮、标签、复选框、下拉菜单、图标和提示必须优先使用对应的 Sens 组件或注册资产。
- 页面中的顶部导航必须调用基础组件 `SensTopNavigation`；不能为了样板间单独复制一个局部产品壳导航。
- 状态矩阵可以用于逐项核对，但不能替代页面中的真实组件和真实交互。
- 不为“看起来像页面”而在样板间中重复绘制基础组件的 DOM、状态或颜色规则。

#### 2.1 组件与页面映射

卡片样板间验收时，必须能明确列出页面使用的基础组件和资产来源。入口配置页面至少核对：

| 页面职责 | 正式承载 | 验收重点 |
|---|---|---|
| 顶部产品壳 | `SensTopNavigation` | 实际结构高度、氛围层、导航主题和层级 |
| 产品侧导 | `ProductShellSideNavigation` | 紧凑、悬浮、锁定展开和内容区投影 |
| 页面标题栏 | `SensPageTitleBar`（`variant="landing"`） | 白底落地页标题、右侧操作；不是灰底分组标题 |
| 分组标题 | `SensSectionTitle` | 灰底分组条、字号、左右内边距、分组间距 |
| 功能入口 | `SensEntryCard` | 彩色图标、标题、辅助说明、选中和键盘激活 |
| 页面操作 | `SensButton` | 按钮层级、动作反馈和状态闭环 |
| 图标资产 | `SensIcon` / 注册图标 | 资产来源、尺寸、颜色和语义 |

页面中的业务文字和统计数据可以使用语义化 HTML 承载，但不得借此重复实现已有组件的视觉或交互规则。

### 3. 以 token 和规则为来源

- 颜色、字体、间距、圆角、边框、阴影、尺寸和栅格必须来自 Token、Foundation 或对应组件规则。
- 页面专属的组合关系可以在样板间定义；跨页面通用的视觉和交互规则应回写到 Foundation 或组件文档。
- 页面中的真实业务图标必须来自图标注册表或已确认的设计资产，不使用临时字符图标或手写 SVG 替代。

### 4. 以真实交互为验收对象

- 页面主路径必须可操作，不能只通过静态 class 或静态色块伪造交互状态。
- 点击、双击、选中、禁用、下拉、返回、提交和反馈等行为，按页面实际语义实现；没有对应语义的状态不额外添加。
- 入口型卡片的选中语义由页面宿主承接，卡片组件只提供视觉和事件能力。
- 页面中出现的操作按钮、更多菜单和浮层必须能真实打开、选择和关闭。
- 复制、提交、返回等动作必须验证真实副作用和用户反馈；仅更新一段提示文字不能视为复制或提交已完成。
- 入口卡片至少验收鼠标点击、键盘 Enter / Space、选中状态和必要时的双击行为；页面没有对应语义时不得额外添加状态。

## 卡片页面组织

- 入口卡片、自由容器卡片和带操作区卡片按业务场景分组展示。
- 真实页面优先使用页面标题、说明和分组标题建立层级，而不是依赖卡片数量制造信息结构。
- 同一页面内应保持卡片宽度、卡片间距、内容对齐和操作区规则一致；不同卡片类型只有在业务语义不同且设计稿明确区分时才并置。
- 大号入口卡片的彩色图标使用 48px 资产，居中于 60px 布局位；该规则属于入口卡片组件与页面组合的共同验收项。
- 入口配置页面的小号入口卡片使用 48px 彩色图标位；大号入口卡片使用 60px 布局位居中承载 48px 彩色图标。
- 同一页面内的卡片栅格应随可用宽度换列，不复制 Figma 画板的固定宽度；换列后仍需保持卡片间距、内容截断和操作区域完整。
- 页面分组的标题、内容、下一组标题之间的间距必须能回溯到页面布局或表单分组规则，不用空白填充演示高度。

## 产品壳组合规则

- 顶部导航的实际结构高度为 `82px`；需要氛围渐变时，氛围层可延展至 `180px`，但不得把正文推到 `180px` 之后。
- 侧导和右侧内容面板从顶部 `82px` 开始叠放；侧导悬浮时覆盖内容面板，使用侧导规则的向外投影，正常 / 锁定状态使用内容面板的向内投影。
- 内容面板的圆角必须使用 `radius/xl`；嵌入式顶部导航保持直角，不能把内容面板的圆角误加到顶导本体。
- 产品壳层级、圆角和投影属于样板间页面的组合验收项；只有跨页面复用的规则才回写 Foundation 或组件文档。

## 响应式与页面验收

样板间页面至少在 1280px、1440px、1920px 三个宽度验收：

- 页面容器、导航和内容区随页面宽度变化；
- 卡片栅格在可用宽度不足时按规则收缩或换列；
- 文案、操作和卡片内容不发生不可解释的遮挡或溢出；
- Portal 浮层不被卡片容器裁切，定位和层级符合页面语义；
- 页面级 20 栏、Drawer / Modal 12 栏规则在适用场景中保持一致。

## 验收要求

- [ ] 已登记 Figma / PRD / 真实页面来源。
- [ ] 页面结构与来源页面的层级、分组和操作关系一致。
- [ ] 页面中使用真实 Sens 组件、注册图标和 Design Token。
- [ ] 真实交互已通过浏览器验收，状态矩阵不替代真实页面验收。
- [ ] 已在 1280px、1440px、1920px 验收页面布局。
- [ ] 已检查卡片、页面容器、导航和 Portal 浮层的宽度、溢出与层级。
- [ ] 页面专属规则已留在样板间；通用规则已回写到 Foundation 或组件文档。
- [ ] 文档、预览页面和实现没有出现互相矛盾的规格。
- [ ] 已列出页面组件与 Token / Foundation 映射，确认没有用页面 CSS 重复实现基础组件。
- [ ] 已分别记录组件调用、Token 来源、视觉、交互和浏览器验收结果，不能用其中一项替代其他项。
- [ ] 页面动作已验证真实副作用与反馈闭环；复制类动作已验证实际剪贴板结果。

## 缺口

- 当前已录入入口卡片页面；另一个已确认的卡片业务页面仍需按本规则补成完整页面。
- 每个页面完成浏览器验收后，再将验证状态从 `Pending` 更新为 `Verified`。
