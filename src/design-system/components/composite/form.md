# 设计系统 skill · 复合组件：复合表单

> 可跨业务复用的表单组合模式，不替代 Form、Table、Radio、Checkbox、Title 等基础组件规则。<br>
> 成熟度：Pilot<br>
> 实现：Implemented<br>
> 验证：Verified<br>
> 来源：Form、Table、Title、Radio、Checkbox 等基础组件规则。<br>
> 预览：`/composite/form`

## 当前收录

| 复合表单 | 适用场景 | 关键规则 | 依赖 |
| --- | --- | --- | --- |
| 带表格表单 | 需要在一张表单中录入或配置结构化多行数据 | 表格永远位于所属标题下方，不受表单上下 / 左右布局影响；灰底标题通栏拉满；标题到表格固定 16px；仅表格外框内缩 16px，与标题文案左边对齐 | Form、Title、Table、Button |
| 联动表单 | 单选或复选的选择结果决定后续字段、卡片或提示是否出现 | 四类联动结构均覆盖上下、左右布局；选中项下有控件、卡片或结果时，标题与整组顶部对齐，Radio / Checkbox 不补 32px 对齐外框；触发选项到关联内容间距为 8px | Form、Radio、Checkbox、Input、Select |
| 卡片表单 | 信息层级较深，需要使用白描边卡与灰底卡建立分组 | 覆盖灰条分组、左右布局卡、关联灰底卡；灰条下内容以 16px 与标题文字对齐 | Form、Title、Card Foundation |
| 抽屉表单 | 在中抽屉内编辑低至中等信息密度的配置 | 使用 `SensDrawer size="medium"`；上下结构用分组灰条，左右结构用控件列和嵌套卡片；内容区独立滚动 | Drawer、TitleBar、Form、Button |
| 气泡卡片表单 | 在当前页面内快速编辑局部配置，或查看关联参数等结构化信息 | 复用 `SensPopover` 的小 / 中 / 大尺寸、定位与关闭闭环；字段仍使用 Form / Input；表格沿用 Table 规则，长内容只滚动内容区 | Popover、Form、Input、Table、Button |
| 带锚点表单 | 页面级长表单需要分组导航与当前位置提示 | 左主内容 + 右纵向锚点；三模式共用贴边 / 顶齐 / 视觉左缘 16；差异只在占位（常驻/挤压）vs 叠层（悬浮）；点击项只切换高亮并页内定位 | Form、Title、Anchor、Input、Select、Radio、Checkbox、Tag、Button |

## 分组间距

同组标题到内容与组间留白是两层规则，不能都使用 16px。

| 关系 | 间距 | Token | 使用条件 |
| --- | ---: | --- | --- |
| 同组：灰色标题 → 本组内容 | 16px | `spacing/vertical/4x` | 标题与字段、卡片或表格属于同一信息组。 |
| 弱分组：一组内容 → 下一组灰色标题 | 28px | `spacing/vertical/7x` | 同一页面任务内的并列小组；需要区分，但不构成独立模块。 |
| 强分组：一组内容 → 下一组灰色标题 | 40px | `spacing/10x` | 独立任务、明显的页面级模块切换，或信息组织需要更强分隔。 |

- 默认优先使用强分组 `40px`；只有设计稿或业务语义明确为同任务下的弱分组时，才使用 `28px`。
- 组间距以“上一组内容底部 → 下一组灰色标题顶部”计算，不包含灰色标题到本组内容的 `16px`。

## 表单动作区

表单动作区消费 Button 的「操作区」规则和 Layout 的操作区插槽，不重新定义按钮等级、状态矩阵或更多收纳。

- 长表单、整页表单和抽屉 / 对话框表单默认优先归入 `Footer action slot`，右对齐；但 Figma 已明确给出标题栏右侧操作时，抽屉使用 `SensTitleBar` 承载返回、放弃和提交，不得为了套用默认规则额外添加 Footer。
- 局部内容块、步骤流或表单段落内的添加 / 上一步 / 下一步，可归入 `Body action slot`，跟随相关内容。
- 操作排序仍按 Button 规则：取消、放弃、上一步等弱操作在左；保存、提交、下一步等主流程操作在右。
- 整页 / 长表单底栏与上一模块（最后一组内容底部）间距使用 `spacing/vertical/10x`（40），与基础 Form「内容区到页脚按钮区」同一档。操作区即使写在 `SensForm` 标签外，该间距仍须成立。
- 表单校验、字段关联、滚动和离开保护由 Form / Layout / 业务流程分别承载；不要通过表单动作区反向定义按钮视觉状态。

## 气泡卡片表单

- 气泡卡片表单只用于局部、轻量且可在当前页面快速完成的操作；点击外部或按 Escape 关闭仍遵循 Popover 规则。
- 短表单使用中尺寸 `SensPopover`，标题、分割线、字段与操作区按 Popover 尺寸规则排列；字段错误态和辅助信息仍由基础 Input / Form 承载。
- 表格型气泡卡片属于 Form 与 Table 的组合：Popover 只承载标题、定位、关闭与内容区滚动；表头、单元格、信息区、分页和表格滚动均遵循 Table 规则。
- 表格型气泡卡片中的三列内容优先使用自适应列宽，表格填满内容区并保留完整外边框；没有真实超宽内容时不产生横向滚动。
- 表格纵向滚动只作用于表格内容区，标题、分页和操作区保持可见；分页器使用正式 `SensPagination`，不直接承载 antd 默认视觉。
- Popover、表格分页器和 Portal 下拉菜单必须使用同一功能色；浮层脱离外层 CSS 变量时，触发器与下拉内容仍需直接接入当前肤色，不能回退到默认神策绿。`SensSelectDropdown` 未传 `functionalSkin` 时跟 AppearanceProvider，样板间不必每个调用点再传一遍。
- 长内容可使用大尺寸 `SensPopover`，卡片最高 600px，仅内容区滚动；存在操作区时，标题与操作区保持可见。
- 需要大量字段、复杂提交、离开保护、蒙层或跨步骤流程时，改用抽屉或对话框，不以 Popover 模拟。

## 表单校验状态

字段级时机、清错和防错见 `form.md`「表单校验」。Input、Select、Radio、Checkbox 只提供自身的 warning / error 视觉，不定义何时出 / 消报错。

- 点提交：所有失败项同时标出，内容滚动容器滚到**第一项**。滚动容器归属 Layout；定位目标由 Form 决定。不要写进 `layout.md` / `product-shell.md`。预览「带表格表单」用同一套页面控制器演示。
- 业务若需「改完仍留错，直到再次提交才清除」，必须在样板间单独声明，不能当默认。

## 分步表单

- 分步表单用于将较长流程拆分为连续步骤；步骤条只负责导航与当前步骤表达，字段内容仍由基础 Form 和控件承载。
- 步骤条与当前步骤内容之间固定留白 40px；步骤表单本身不额外添加灰色描边外框或卡片背景，避免与基础控件容器重复。
- 每个步骤独立展示字段、辅助文案、错误和选中状态；切换步骤不应把未完成步骤的校验状态静默清除。
- 带步骤条的表单默认分步校验。点下一步或点步骤条切走时，校验**当前步**全部表单项，并按字段级规则展示报错。
- 步骤条、下一步、上一步都能换步。下一步有错仍可离开，不拦截。无错通过后该步 `completed`，序号变为绿对勾再进入下一步。有错离开则不算完成，保持 **等待 + 红色数字**。“上一步”返回时保留已填写值；最后一步使用一级按钮“提交”。
- 未改完带着错误离开（步骤条 / 下一步 / 上一步）：该步保持 **等待 + 红色数字**，不得因 `current` 变大而自动变成已完成。
- 整表点“提交”再校验：已完成步骤被打回为 **已完成 + 红色对勾**；当前最后一步失败仍是红色数字。步骤条标出所有含错步骤，并跳到**第一个出错步**的**第一项**。预览分步表单按此跳步并滚到该步第一项。
- 分步表单必须用 `completed`（或显式 `status`）表达是否完成，不能只靠 `current` 下标把未完成的报错步推成 finish。
- 步骤页面可按业务需要采用上下或左右布局，但不在步骤表单中重新定义基础组件的字号、颜色和交互。
- 召回规则等指定产品线步骤的顶层标题使用 `SensSectionTitle variant="productLine"`（专用大尺寸：左侧绿条、18 / 28、无灰底、无右侧按钮组）；辅助文案走 `description`，与标题同一行基线对齐，不得另起段落或用 CSS 把通用灰条剥成伪专用标题。
- 召回规则步骤：专用标题左右缩进 `spacing/horizontal/6x`（24）；描边卡片左右缩进 `spacing/7x + spacing/2x`（36，无独立 9x）。绿条在 24 起点，标题文字与卡片左缘对齐（条宽 4 + 间距 8 = 12）。
- 「选择可推物品」与「补齐规则」是两个独立产品线模块，组间使用强分组 `spacing/10x`（40）。补齐规则标题使用 `optional="(选填)"`，辅助文案走 `description`。
- 补齐规则一张描边卡内含两块：可推物品属性筛选 + 截取及排序方式，块间距 `spacing/vertical/5x`（20）。筛选行第三段为选择器与数字输入的拼缝组合框（右缘圆角切掉、中间重叠 1px）。卡下复选「出随机推荐结果」与卡片左缘对齐。
- 筛选行且/或连接器的「且」块跟随当前功能色（`--sens-skin-primary`）；「或」块走 `background-01-transparent` / `text-sub-color-transparent`，竖线保持中性。不得把整图 mask 成功能色，也不得把「且」底写死为神策绿。
- 预览 Demo 分开提供第一步与第二步，避免用单一切换器同时联动所有字段状态。
- Figma 参考：`54:14655`（提交 / 报错 / 选中）、`54:14219`（创建推荐策略-召回规则）、`54:14651`（补齐规则）；校验时机与提交定位 `2160:77795`。

## 带锚点表单

长表单与右侧锚点的**组合规则**。三种 mode 的视觉（项高、选中竖线、悬浮卡片圆角 / 投影、收起条宽度）见 `anchor.md`；滚动容器、钉住与产品壳层级见 Layout。本小节不重复那些组件私有规则。

- 左侧为多分组表单内容，右侧为 `SensAnchor`；锚点项与灰色分组标题一一对应。
- 点击锚点项只切换高亮并页内定位，不接入路由、后端或业务提交。
- `mode="popover"` 是锚点「悬浮卡片」命名，**不是** `SensPopover`。
- 三种展示语义（Demo「锚点展示」切换；差异只在占位还是叠层）：
  - **常驻** `fixed`：始终展开，占位收窄主列。
  - **点击悬浮** `popover`：默认收起；展开为叠层遮盖，不挤主列；仅收起条让位。
  - **点击挤压** `push`：默认收起；展开后占位收窄主列。
- 三种模式共用定位：
  - 贴内容白板右缘，右边距 0。
  - 灰标题背景右缘、通栏卡右缘 → 锚点**视觉左缘**（展开：轨道 / 选中条；收起：收起条）`spacing/horizontal/4x`（16）。量视觉左缘，不是定位外盒。灰条与通栏卡同一右缘。通栏卡**左缘**对齐所属字段标题（如「条件配置」「疲劳度」），不要拉到灰条外缘；**只**用负 `margin-right` 消掉 `group-content` 右边的 16。选择器用子选择器，不得打到卡内嵌套字段。卡内上下布局仍是控件跟自己的标题左对齐。reserve 公式扣 board 右 padding **和** 1px 描边。
  - 锚点顶与第一个灰标题顶对齐；标题滚出后钉在内容区顶 + `spacing/vertical/4x`（16）。
- Demo 须保证收起条 / 悬浮卡片完整可见；不得为可见性覆盖 Anchor 的右侧锚定规则。
- 三种模式均 portal 到 `document.body` 钉住。选中字和左侧竖线的功能色由 `SensAnchor` 在根上写入当前 Functional Skin，不能靠继承外壳 `--sens-skin-primary`（会回落神策绿）。
- 分组、字段、卡片、底栏间距与控件宽度遵循基础 Form 与下文录入边界，不因带锚点另开档位。默认强分组 40；字段间距 20；卡内分割线上下 16；底栏距上一模块 40。
- Figma 参考：设计系统绿稿分组页；表单组件专档悬浮样张 `62:17060`。

## 录入边界

- 复合表单只组合已 Ready 的基础组件与 token。遇到缺失的基础组件、图标或语义 token，先标记 `Missing / To Confirm`。
- 职责拆分：页面级滚动容器、钉住与产品壳遮挡由 Layout / 页面壳负责；锚点三种 mode 的视觉与展开由 `SensAnchor` 负责；长表单与灰标题对齐、主列让位、叠层 vs 占位由「带锚点表单」负责。不要在单个样板间把上述行为写成不回写文档的私有契约。
- 真实业务对象、默认值、字段数量、权限和提交流程进入样板间或案例，不写进复合组件。
- 带表格表单中，外层板块先使用 `spacing/horizontal/4x`（16px）左右 padding；灰底标题通栏拉满内容区（宽度自适应），标题文案再使用其自身 `spacing/horizontal/4x`（16px）内边距。灰底标题到表格纵向固定 `spacing/vertical/4x`（16px）。仅表格外框额外缩进 `spacing/horizontal/4x`（16px），与灰底标题文案共用对齐线，不得把灰底标题容器一起缩进。
- 联动表单与卡片表单中，选项到其关联控件、关联卡片或关联结果使用 `spacing/vertical/2x`（8px），不要用表单项 20px 行距。关联 Radio / Checkbox 使用 `itemHeight="content"`，不保留 32px 对齐盒。Radio 与关联卡必须包在同一字段内容区（如 `form-templates-linked-content`），不能把卡做成下一个独立表单项。
- 关联卡片填满当前 Form 控件区，不受 `form/control/max-width` 的常规字段上限约束。**通栏的是卡片本身**；卡片内的 Input / Select 等仍遵守 `form/control/max-width`（当前 600），不得随卡片拉满。取消卡片控件区上限时只能打在该项的直接 control 上，不能用后代选择器。卡片内的 Form 布局继承外层 Form，外层左右则卡内左右，外层上下则卡内上下。卡内组标题与字段标题共用卡片内边距左缘，不要再套一层 `sens-form-group-content` 的 16 缩进（那一层只服务灰条标题下的同组内容）。
- 关联卡片标题按卡片内信息层级决定：单一内容组使用 14px 组标题；存在明确并列分组时，才按分组规则使用更强标题或灰条。

## 嵌套卡片与表达式组

- 卡片内只有一个内容组时，组标题使用 `font-size/m`（14px）+ `line-height/m`（22px）+ medium；不使用灰色标题条，也不因处于卡片内自动升为大标题。
- 只有卡片内存在并列信息组、且确实需要区分层级时，才使用灰条或更强标题；灰条不是装饰性容器。
- 卡片内边距使用 `spacing/4x`（16px）；卡片内分割线与其上下关联内容的间距均为 `spacing/vertical/4x`（16px）。
- 表达式、多列筛选等跨行结构应由同一个内容列容器统一承载。后续动作与第一列控件共用左对齐线，不依赖 antd 容器层级、`display: contents`、负 margin 或独立偏移。
- 宽度应由内容列自适应分配：固定内容列使用其内容所需宽度，承载多选回显或长文本的列占用剩余可用宽度并允许内部收纳；不得越出卡片。
- 连接线、括号和方向性图标优先引用正式 Sens / Figma 资源；如需翻转，只翻转具体资产，保持 DOM 内容与视觉顺序不变。
