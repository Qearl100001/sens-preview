# 设计系统复合组件：通知系统

> 成熟度：Pilot<br>
> 实现：Implemented<br>
> 验证：Pending<br>
> 预览：`/composite/notification`

## 定位

- 「通知系统」是复合组件的组织分类与演示入口，不是包办全部通知能力的单一组件。
- 页面按复合表单的方式分项展示：页头说明、顶部选项、当前项内容。当前只有一项「通知配置与对象选择」，通知渠道和对象选择在这一项里一起看。
- 各项独立定义边界、依赖和验收，不把真实业务整页直接定义为复合组件。
- 真实事件名称、通知文案、默认值、业务对象、保存流程和后端集成由样板间或调用方负责。

## 当前收录

| 通知配置与对象选择 | 同一项里组合通知渠道、接收范围、对象选择与回显，以及邮件 / Webhook 配置入口 | [`notification-settings.md`](./notification-settings.md)、[`recipient-selector.md`](./recipient-selector.md) |

## 后续扩展

- 新增通知能力时，先判断它是独立可复用的组合模式、现有组件的子能力，还是具体业务页面场景。
- 独立组合模式使用单独组件与规则文档，并作为新的演示项加入本页；对象选择这类共享子能力留在所属项内，不单独占一项。
- 只有业务特定标题、说明、默认值、字段和提交流程时，才新增或扩展通知样板间；不要把业务页面反向并入通知系统组件。
- 演示入口只呈现当前已实现内容，不预先添加空白占位项。

## 验收

- 顶部当前只有「通知配置与对象选择」一项；对象选择在该项内打开，不再单独占一个选项。
- 该项调用 `SensNotificationSettings`，对象选择复用 `SensRecipientSelector`；总览文档、子组件规则、Preview 与样板间职责一致。
- 当前内容的交互与视觉验证仍以各子组件和通知配置样板间的验收规则为准。
