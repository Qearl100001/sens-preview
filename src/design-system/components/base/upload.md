> 一句话定位：统一的文件选择与上传状态呈现组件，支持文件列表和图片缩略格两种样式。
> 成熟度：首轮实现 · 待浏览器验收
> 实现：`SensUpload`
> 验证：待按 `docs/agent-rules/page-evaluation-checklist.md` 验收

> 预览：`/components/upload`

## 边界

负责文件选择、可选拖拽接收、文件列表/图片格呈现，以及上传状态、只读、禁用、必填错误展示。业务层负责服务端传输、模板下载、格式与内容校验、大小限制和业务错误决策。

## 核心规则

- 一个 `SensUpload` 通过 `mode="file" | "image"` 提供两种视觉呈现，不拆成两个组件。
- `dragEnabled` 开启拖拽；文件/图片呈现共享 `files` 与 `onChange` 数据契约。
- 文件项 `status` 支持 `uploading`、`done`、`error`；进度、错误、重试和预览由调用方接入。
- `disabled` 禁用整个组件；`readOnly` 保留内容但不提供修改操作；`maxCount` 到达后隐藏新增入口。
- 不接收内容校验、模板下载或真实网络传输逻辑。

## Token / 组件映射

见 [`upload.design.md`](./upload.design.md)「Token 映射」。操作按钮复用 `SensButton`，图标复用 `SensIcon`；组件颜色、字体、间距、圆角使用现有语义 Token。

## 验收

- [ ] 文件与图片两种真实 Demo 和状态矩阵。
- [ ] 本地选择与拖拽、达到数量上限、删除、重试/预览回调。
- [ ] 上传中、完成、失败、必填错误、只读、禁用状态。
- [ ] 1280–1920 宽度、长文件名、缩略格换行。
- [ ] TypeScript / 生产构建、Prototype Kit 打包和浏览器交互验收。

## 缺口与待确认

- 首轮规则没有限定默认文件大小和可接受格式，交由调用方设置。
- 上传进度与服务端失败/重试完全由业务接入；组件本身不伪造传输成功。
- Figma 八页中的场景帮助文案和单文件重新上传用词由调用方按业务配置。
