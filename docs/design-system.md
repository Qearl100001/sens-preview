# Sens.Design — design-system.md

> Sens.Design 是面向企业软件和复杂业务场景的设计系统。\
> 它通过稳定的视觉语言、组件规则和一致性交互流程，帮助用户准确、高效地完成任务。

## 1. 设计价值

Sens.Design 的设计目标不是单纯追求视觉美观，而是帮助客户和用户获得可衡量的业务价值。

设计决策应建立在真实业务需求之上，同时考虑客户目标、用户任务、角色关系、操作流程和长期使用效率。

### 1.1 准确性

信息传达准确是第一原则。

- 用户需要清楚地知道自己在哪里。
- 页面需要明确当前对象、状态和可执行操作。
- 文案应准确、无歧义，并保持语境统一。
- 操作结果需要及时反馈。
- 不可执行操作需要说明原因。
- 推荐操作、风险操作和不可逆操作需要有准确预期。

### 1.2 高效率

企业软件的核心价值之一是帮助用户高效完成任务。

- 一个操作区域应有明确的核心任务。
- 主操作应清晰、唯一。
- 操作路径应尽可能短。
- 复用已有交互习惯，避免无意义创新。
- 高频信息应便于扫描。
- 复杂信息应通过分组、层级和渐进展示降低理解成本。

### 1.3 无障碍

当前设计系统提供企业办公场景下的基础无障碍保障。

- 状态不能只通过颜色表达。
- 状态色旁应有文字、图标或形态辅助。
- 投影仪、共享屏和高亮环境下仍应识别主要信息。
- 页面在 1280px 至 1920px 的常见企业设备宽度中保持可用。
- 键盘操作、焦点反馈和禁用原因应清晰可见。

### 1.4 生机

情感化表达应克制、自然，并服务于任务。

- 帮助信息应触手可及。
- 空状态应提供明确下一步。
- 反馈文案应直接、友好，不说教。
- 图形、插画和色彩不应干扰核心任务。

## 2. 视觉语言

Sens.Design 的整体视觉表达应保持专业、清晰、沉稳和克制。

界面强调信息层级与任务效率，不依赖大面积装饰、复杂渐变或过度卡片化建立视觉效果。

### 2.1 密度

- 采用适合 B 端产品的中等信息密度。
- 基础布局以 4px 为最小间距单位。
- 页面留白应服务于分组和扫描，不追求过度宽松。
- 同一层级元素保持稳定的尺寸和间距关系。

### 2.2 对齐

- 页面正文和表单内容默认左对齐。
- 标题、字段、表格和操作区应建立稳定的纵向对齐关系。
- 图标和文字需要保持视觉居中。
- 不使用无意义的居中布局弱化信息扫描效率。

## 3. 颜色

颜色分为基础色板、功能色、导航主题色、中性色和固定状态色。

### 3.1 基础色板与色阶

基础色板是设计源、审计源和换肤映射源，不直接作为组件代码的颜色入口。组件和页面使用语义颜色；只有颜色基础样张、换肤映射和审计工具可以读取基础色板路径。

色彩定义采用 HSB 模型。基础色相先通过 HSB 色相环筛选，再根据视觉相似度收敛为主题色。每个彩色主题使用 16 个色阶，第 10 阶为基准色；子夜黑和象牙白使用各自的中性色阶。

| 色阶 | 语义 | 用途 |
|---:|---|---|
| 16–13 | 深色区域 | 深色文字、深色图标、深色背景和高强调状态 |
| 12 | 点击 / active | 点击、pressed、active 状态 |
| 11 | 强调深色 | 深色文字或深色品牌表达 |
| 10 | 基准色 | 默认功能表达、品牌实色 |
| 09–08 | 交互色 | 悬停、链接悬停或中等强调 |
| 07–06 | 弱化色 | 禁用、弱化和辅助表达 |
| 05–01 | 浅色区域 | 浅色背景、选中背景和低强调承载 |

对于使用主题功能色的功能性控件，基础色阶的默认角色映射为：默认使用 10，悬停使用 8，点击使用 12，禁用使用 6，禁用悬停使用 5。这个映射不是所有颜色和所有组件的全局状态规则；链接、固定状态色和数据语义色使用各自的语义规则。选中背景、点击背景和浅色背景属于语义衍生色，不强制等同于单个色阶。

色阶衍生遵循以下方向：深色区域保持色相、提高饱和度并降低明度；浅色区域保持色相、降低饱和度并提高明度。任何组件不得因为视觉相近而跨主题直接借用另一套基础色阶。

当前基础色板包括：旭日红、沙丘金、原野黄、青柠绿、极光绿、神策绿、山水蓝、冰绽蓝、兰花紫、波光紫、云霞粉、子夜黑，以及象牙白中性色阶。子夜黑是常规产品壳主题，不代表暗色主题；当前产品不定义暗色主题。

颜色样张应同时展示完整色阶、基准色角色、语义映射和对比度示例。

### 3.2 功能色

功能色用于表达：

- 主操作
- 选中状态
- 功能性悬停
- 点击状态
- 聚焦状态
- 激活投影
- 功能性浅色背景

当前已确认七组功能色：

- 神策绿
- 冰绽蓝
- 青柠绿
- 极光绿
- 山水蓝
- 兰花紫
- 波光紫

默认功能色为神策绿。旭日红、原野黄、沙丘金和云霞粉等品牌主题使用冰绽蓝功能色；品牌色与功能色不因名称相近而强绑定。

功能色只改变视觉表达，不改变组件结构、尺寸、交互逻辑和信息层级。

### 3.3 导航主题色

导航主题色用于：

- 顶部导航
- 侧边导航
- 标题栏
- 页面背景
- 产品壳菜单

导航主题色与组件功能色相互独立。

当前导航主题共 12 套：

- 神策绿、冰绽蓝、原野黄、青柠绿、沙丘金、旭日红
- 极光绿、山水蓝、兰花紫、波光紫、云霞粉、子夜黑

每套导航主题必须同时定义以下七个产品壳颜色槽位：

| 槽位 | 设计职责 |
|---|---|
| 顶导背景 | 顶部导航的主题基础背景，允许使用主题专属渐变 |
| 氛围层 | 顶部导航的统一叠层结构，默认由两层白色 radial 和中性底线组成 |
| 侧导背景 | 侧边导航的主题浅色背景，允许使用主题专属渐变 |
| 标题栏背景 | 页面标题栏、上下文标题区的主题承载背景 |
| 页面背景 | 产品壳下内容区的主题浅色背景 |
| 品牌实色 | 导航选中文字、图标、短线等品牌强调色 |
| 品牌浅底 | 导航选中或悬停菜单的品牌浅色背景 |

12 套主题的具体颜色规格维护在 Navigation Color Foundation 中。氛围层没有为某套主题单独给值时，统一复用叠层结构，只替换顶导基础背景。子夜黑属于常规浅色产品壳主题，不代表暗色模式。

### 3.4 中性色

中性色用于构成稳定的内容底座：

- 主要文字
- 次要文字
- 辅助文字
- 禁用文字
- 普通图标
- 普通边框
- 分割线
- 卡片背景
- 表单背景
- 表格背景
- 页面内容背景

普通中性色默认不参与功能色换肤。

### 3.5 固定状态色

以下颜色默认不跟随功能色换肤：

- 链接
- 成功
- 提醒
- 警告
- 错误
- 危险操作
- 上涨
- 下跌
- 不变

状态色必须对应明确语义，不能只因为视觉需要而使用。

### 3.6 语义颜色与组件状态

颜色状态规则按颜色家族和组件职责划分，不存在一套覆盖所有组件的“默认 / Hover / Active”映射。

| 颜色家族 | 默认 | Hover | Active / Pressed | 适用范围 | 是否换肤 |
|---|---|---|---|---|---|
| 功能色 | `component-primary` | `component-hover` | `component-active` | 主按钮、选择控件、功能性选中态 | 是 |
| 链接色 | `link-color` | `link-hover-color` | `link-active-color` | 链接按钮、表格操作、帮助文档链接 | 否，固定蓝色 |
| 成功色 | `success-color` | 通常无 | 通常无 | 成功结果、状态标识 | 否 |
| 提醒色 | `info-color` | 通常无 | 通常无 | 提醒、风险提示 | 否 |
| 警告 / 错误 / 危险 | `warning-color` | 交互组件使用 `warning-color-hover` | 危险操作使用 `warning-color-active` | 错误状态、警告提示、破坏性操作 | 否 |
| 数据语义色 | `rise-color` / `fall-color` / `flat-color` | 无 | 无 | 上涨、下跌、不变等数据表达 | 否 |

成功、提醒、上涨、下跌和不变默认是被动语义，不自动生成交互状态。一个承载这些语义的可交互组件，应根据组件职责选择功能色、链接色或危险操作色，不能直接把状态色当作按钮的 Hover / Active 色。

“警告”和“危险”共用旭日红状态链，但职责不同：警告用于提示风险，危险用于删除、撤销、清空等破坏性操作；当前“错误”也复用这组红色 token，antd 映射保持 `warning-color` → `colorError` 的现状。

## 4. 字体与排版

### 4.1 字体

默认使用系统中文无衬线字体：

```css
-apple-system,
BlinkMacSystemFont,
"Segoe UI",
"PingFang SC",
"Hiragino Sans GB",
"Microsoft YaHei",
"Helvetica Neue",
Helvetica,
Arial,
sans-serif,
"Apple Color Emoji",
"Segoe UI Emoji",
"Segoe UI Symbol"
```

字体主权在 Sens.Design：唯一常量 `SENS_FONT_FAMILY`（`src/design-system/typography.ts`）。`buildAntdTheme` 将同一栈灌入 antd `token.fontFamily`（承接层，不当字体定义）；入口调用 `applySensFontFamilyToDocument` 挂到 `html, body, #root`。不新增字体族 token。

### 4.2 基础文字

- 默认正文：14px / 22px。
- 辅助文字：12px / 18px。
- 标题使用已定义的字号和字重层级。
- 正文默认字重为 400。
- 标题通过字号、字重和间距建立层级，不依赖颜色夸张强调。

### 4.3 文案规则

- 按钮文案以动词开头。
- 避免使用含义模糊的“确定”。
- 常规无图标两字按钮可以增加中文字间距。
- 链接、虚线添加、更多、图标按钮不强行增加中文字间距。
- 按钮文案不换行。
- 占位符不能替代帮助文字。
- 过长文案需要截断时，应提供查看完整内容的方式。

## 5. 间距与尺寸

### 5.1 间距

基础间距遵循 4px 倍数关系，常用档位包括：

- 4px：图标与文字、紧凑局部间距。
- 8px：标签与控件、关联元素间距。
- 12px：小型容器和紧凑操作区。
- 16px：组件间距、标题与内容、卡片间距。
- 20px：常规表单项垂直间距。
- 24px：页面和大型容器内边距。
- 28px：同一任务内的弱表单分组间距。
- 40px：独立模块或强表单分组之间的间距，默认优先使用。

组件专属间距以具体组件规范为准。

表单分组间距按“上一组内容底部到下一组标题顶部”计算，不包含下一组标题到本组内容的内部间距。灰色分组标题到同组内容通常使用 16px。

### 5.2 控件尺寸

当前主要控件尺寸：

- 大尺寸：32px。
- 小尺寸：24px。

尺寸选择取决于使用场景：

- 页面、抽屉、对话框使用大尺寸。
- Dropdown、Popover 等紧凑空间可以使用小尺寸。
- 同一个操作区不应随意混用多个尺寸。

### 5.3 圆角

圆角按形态选择：

- 普通控件：使用基础控件圆角。
- 卡片和容器：使用容器圆角。
- 胶囊标签页和标签：使用胶囊圆角。
- FAB 和图标按钮：根据形态使用圆形或对应圆角。

不通过任意增加圆角营造“现代感”。

## 6. 投影与层级

投影用于表达空间关系和交互反馈，不作为装饰。

主要类型：

- 组件悬停反馈。
- 卡片层级。
- Dropdown、Popover、Tips 等浮层。
- Drawer 等大型浮层。
- 输入、选择和按钮的功能激活环。

原则：

- 层级越高，投影范围越大。
- 同一容器内不叠加多个无意义投影。
- 普通文字按钮 active 不使用功能色外投影。
- 实体按钮、描边按钮和虚线按钮可在 active 时使用功能激活环。
- 普通功能控件的聚焦外环和激活投影跟随当前功能色；链接按钮使用链接语义的 active 指示；警告 / 危险控件使用警告红的 active 指示；被动状态标识不自动增加交互投影。
- 聚焦外环与激活投影是不同的触发语义：前者用于 `focus-visible`，后者用于按下或激活反馈；两者可以共享同一语义投影源，但不能因此混淆状态规则。
- 浮层必须脱离普通文档流，并按照交互优先级保持稳定的层级关系。

### 6.1 浮层 Z-index

Z-index 用于维护页面内容、产品壳、浮层和全局反馈之间的覆盖关系。数值只表达层级，不表达组件视觉重要性。

| 数值 | 层级 | 适用内容 | 规则 |
|---:|---|---|---|
| 0 | 页面内容 | 普通页面内容、卡片、表格、表单 | 默认层级，不主动设置更高值 |
| 10 | 固定产品壳 | 固定顶部导航、固定侧边导航、局部 sticky 区域 | 不应覆盖 Modal 或 Drawer |
| 100 | 页面内悬浮操作 | FAB、页面内固定操作、局部悬浮工具 | 只覆盖普通页面内容和固定产品壳 |
| 1000 | 大型浮层 | Drawer、Modal 及其蒙层 | Drawer 当前实现值为 `1000`；面板应在自身容器内位于蒙层之上 |
| 1050 | 交互浮层 | Dropdown、Select、Popover、下拉菜单 | 可以覆盖页面内容、产品壳和大型浮层内部内容 |
| 1060 | 说明浮层 | Tips、Tooltip、局部帮助说明 | 当前 `SensTips` 实现值为 `1060`，应高于普通交互浮层 |
| 1100 | 全局反馈 | Message、Notification、全局结果提示 | 用于跨页面或跨容器的结果反馈 |

使用规则：

- 同一层级内优先通过 DOM 顺序、定位容器和局部 stacking context 解决覆盖关系，不随意继续增加数值。
- Portal 浮层必须明确自己的层级归属，不能因为脱离触发容器就使用任意高值。
- Drawer、Modal 内部的 Dropdown、Popover、Tips 可以使用各自层级，从而覆盖当前浮层内容。
- 组件实现必须优先消费对应的统一层级值，不在业务页面中临时手写 z-index。
- 新增浮层类型时，先判断它属于页面内悬浮、大型浮层、交互浮层、说明浮层还是全局反馈，再决定是否新增层级。

## 7. 图标

- 默认使用线性图标。
- 填充图标只用于明确状态、警告、下拉方向或特定数据图形。
- 图标必须表达实际含义，不能作为装饰滥用。
- 图标颜色根据主要、次要、禁用、警告等语义选择。
- 图标按钮必须提供可理解的名称或 Tips。
- 图标和文字同时出现时，图标通常位于文字左侧。
- 下拉方向、展开收起等图标可按交互结构放置在右侧。

## 8. 布局与响应式

### 8.1 页面骨架

当前主要布局包括：

- T 型布局：产品导航、侧边导航和内容区。
- 上下布局：顶部导航与主内容区。
- 上下文侧栏布局：主内容与页面内辅助导航或目录。

产品壳、页面侧栏和组件内部侧栏属于不同层级，不能混用规则。

#### 产品壳层级

带产品壳的页面遵循“视觉氛围层不占正文流”的结构：

- 顶部导航的实际结构高度为 `82px`。
- 需要氛围渐变时，氛围层可以延展到 `180px`，但不能把正文推到 180px 之后。
- 侧边导航和右侧内容面板都从页面顶部 `82px` 开始叠放。
- 层级顺序为：顶部导航与氛围层 → 侧边导航 → 右侧内容面板 → 内容区浮层。
- 当前产品壳侧边导航的固定展开宽度为 `220px`；它是产品壳结构值，不是通用页面左栏 token。
- 侧边导航悬停展开时覆盖内容面板，使用向外投影；固定或锁定展开时，内容面板使用向内投影。
- 内容面板的外部圆角使用最大容器圆角 `radius/xl`；嵌入式顶部导航保持直角。

顶部导航是否启用氛围层由页面设计决定；没有氛围层的页面只保留 82px 的导航结构，不自行添加渐变。

### 8.2 栅格

- 页面级布局使用 20 栏栅格。
- Drawer、Modal 和局部容器使用 12 栏栅格。
- 栅格负责内容区域分配，不替代组件内部间距。

### 8.3 宽度适配

当前重点支持 1280px 至 1920px 企业桌面环境。

验收至少覆盖：

- 1280px
- 1440px
- 1920px

窄屏时应优先保证任务可完成和信息可读。必要时允许内容区滚动，不强行压缩组件到不可用尺寸。

响应式规则的 P0 边界已经收口：`1280px`、`1440px` 和 `1920px` 是正式验收宽度；响应式只调整页面可用内容宽度和内容承载方式，不改变页面骨架、20 栏页面级布局、Drawer / Modal 12 栏规则、组件尺寸或交互语义。

- `1280px`：产品级电脑端最小画布，必要时横向滚动，不强制切换移动端结构。
- `1440px`：默认设计画布，内容按可用宽度自适应。
- `1920px`：允许内容区域更舒展，不通过无意义放大组件制造差异。
- 产品壳滚动收起、标题栏吸附、侧导联动和表头吸顶属于 Layout 行为，不自动归入响应式规则，需按各自组件或页面行为单独验收。

## 9. 一致性交互流程

一致性交互围绕“对象”展开。

### 9.1 创建

创建是从 0 到 1 产生长期对象。

```text
进入创建
→ 输入信息
→ 提交
→ 返回入口
→ 成功反馈
```

创建过程有有效输入时，放弃操作原则上需要挽留。

### 9.2 添加

添加是创建或编辑过程中的局部新增。

普通添加应在原位置产生结果，不应打断当前主任务。

### 9.3 查看

查看用于在稳定状态下阅读已有对象。

- 查看态与编辑态必须明确区分。
- hover Tips 不等于查看。
- 查看容器需要明确关闭或返回入口。

### 9.4 更多

更多用于同一容器内的局部展开、收起或操作收纳。

- 展开内容与原容器保持同一层级。
- 更多菜单不替代对象详情。
- 表格操作过多时可以收入更多菜单。

### 9.5 编辑

编辑针对已有对象。

```text
进入编辑
→ 修改
→ 保存
→ 返回
→ 成功反馈
```

未发生有效修改时，保存操作建议禁用。

### 9.6 删除

删除是将长期对象从 1 变为 0，原则上需要挽留。

```text
触发删除
→ 确认删除
→ 完成删除
→ 结果反馈
```

确认操作使用警告语义，取消操作保持弱化。

### 9.7 放弃

放弃用于终止创建或编辑：

- 创建过程中产生有效输入后，放弃需要挽留。
- 编辑过程中发生有效修改后，放弃需要挽留。
- 未修改内容时可以直接退出。
- 临时添加通常不需要挽留。

### 9.8 移除

移除用于删除临时或过渡性内容。

移除通常可以直接完成，不按长期对象删除流程处理。

### 9.9 二次提示

二次提示用于关键提交或不可逆操作。

- 普通提交不默认增加二次提示。
- 重要资源占用、关键流程流转和不可逆结果需要二次提示。
- 删除挽留与提交二次提示是两类不同流程。

## 10. 组件设计原则

### 10.1 按钮

- 一个操作区域只设置一个一级操作。
- 页面标题区和 Footer 中，主操作通常位于右侧。
- 内容区局部操作按任务顺序排列。
- 操作过多时使用更多菜单收纳。
- 一级、二级、三级、链接、警告、虚线、更多、下拉和 FAB 按语义选择。
- 链接按钮使用链接色状态链，不使用主题功能色状态链；危险按钮使用警告红状态链。
- 警告色只用于明确的风险和破坏性操作。
- 虚线按钮用于原位添加，必须带添加图标。
- FAB 必须通过图标名称或 Tips 解释操作含义。

### 10.2 输入与选择

- 输入框用于自由录入。
- 选择器用于从有限选项中选择。
- 搜索用于检索和过滤，不能与普通输入框混用。
- 占位符说明输入内容，不承担长期帮助信息。
- 错误、警告和禁用状态需要明确反馈。
- 普通功能控件的聚焦边框和激活环跟随当前功能色；链接和危险语义按各自颜色家族处理。
- 下拉浮层必须与触发框保持状态和主题一致。

### 10.3 表单

- 默认采用垂直表单布局。
- 标签、控件、帮助说明和错误提示保持稳定顺序。
- 字段分组依据任务和信息关系，不按视觉需要随意分组。
- 联动字段应靠近触发条件。
- 表单操作区遵循按钮优先级。
- 复杂表单可使用标题分组、卡片分组或带表格结构。
- 顶层分组标题可以使用灰底标题条；同组标题到内容通常为 16px。
- 同一任务内的弱分组使用 28px；独立模块之间默认使用 40px。
- 28px 与 40px 是分组层级规则，不是所有页面都必须同时使用的固定间距。

### 10.4 表格

- 表格优先支持扫描、比较和批量处理。
- 表头、单元格、操作列和分页保持稳定关系。
- 行操作不宜过多，溢出操作收入更多菜单。
- 录入型表格、树表和嵌套表格属于不同组合模式。
- 分页是独立组件，不默认写入基础表格内部。

### 10.5 卡片

卡片用于承载具有稳定关系的一组内容或操作，不作为单纯的装饰性容器。

- 卡片可以包含标题区、内容区和操作区，具体区域按任务需要启用。
- 卡片内部应保持清晰的内容层级和稳定的内边距。
- 卡片之间通过间距、边界和内容关系建立分组，不依赖过度阴影。
- 卡片内的操作遵循按钮优先级和对象操作流程。
- 普通卡片默认使用 `6px` 圆角；宽度由页面容器和栅格决定，不复制 Figma 画板固定宽度。
- 卡片可以包含标题区、内容区和操作区；操作区存在时，操作栏总高度为 `40px`，上下 padding 为 `9px`。
- 操作区分割线应通栏铺满卡片宽度；内容区到分割线通常保留 `12px` 间距。
- 入口型卡片的大号布局位为 `60px`，内部居中承载 `48px` 彩色图标；图标资源不按普通线性 / 面性图标尺寸缩放。
- 卡片的选中、悬停、操作菜单和键盘行为必须符合对应卡片类型的语义；页面组合不应重复实现基础卡片状态。

### 10.6 导航

- 顶部导航和侧边导航属于产品壳。
- 标签页用于同一页面或容器内的内容切换。
- 面包屑用于表达对象层级和返回路径。
- 页面标题栏承载当前位置、辅助信息和页面级操作。
- 导航主题色与组件功能色独立。

### 10.7 反馈

- Message 用于短暂、轻量的全局反馈。
- Alert 用于页面内持续可见的信息或风险提示。
- Tips 用于解释局部控件或补充短文案。
- Drawer 用于不中断页面上下文的创建、编辑或查看任务。
- 不同反馈组件不能只因外观相似而混用。

## 11. 换肤验收原则

换肤验收必须同时检查：

- 当前主题属性。
- 功能色和导航主题组合。
- 默认、hover、active、focus、disabled、loading。
- 需要区分功能色控件、链接按钮、警告 / 危险控件和被动状态标识，不能只验收一套主色状态链。
- 真实组件与状态样张。
- Dropdown、Popover、Tips 等浮层。
- 链接和状态色是否保持固定语义。
- 中性色是否被错误换肤。
- 12 套导航主题和 7 组功能色是否都能在预览设置中被选中。
- 推荐映射以及至少一组非推荐组合是否能真实渲染。
- 主题切换后 CSS 变量、组件 token 和浮层 Portal 是否仍指向当前主题。

结构、尺寸、交互和信息层级不能因为换肤改变。

## 12. 当前不定义的内容

当前版本暂不定义：

- 完整动效系统。
- 插画和图表色板。
- 尚未录入或验证的组件详细规格。

尚未完成的规则确认后再进入后续版本；已定义的产品壳、卡片和表单基础规则不应被页面实现重新解释。
